# Changelog

All notable changes to GakrCLI will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Message queue, event driver and goal evaluation**: `utils/messageQueueManager.ts` and `utils/queryEventDriver.ts` give queued input and query events a single owner, and `services/goal/controller.ts` with `evaluator.ts` assess whether a run met its goal before it reports completion.
- **WebBrowserTool DOM-tree / highlight-index system**: Replaced Playwright's `ariaSnapshot({ mode: 'ai' })` + `aria-ref=` locators with a ported version of browser-use's interactive-element extraction (`domTreeScript.ts` verbatim from upstream, `domService.ts` for the TS wrapper, `domTypes.ts` for the data model + renderer). The numbering the LLM sees is unchanged in spirit — small integers from the latest `get_state` — but each index now backs a stable xpath in a `SelectorMap` plus bounding-box/viewport data, and `get_state` only paints highlight overlays when a screenshot is requested. The old `[ref=eN]` / `aria-ref=eN` selector format now fails fast with a "call browser_get_state again" message instead of a 10-second timeout. No LLM logic added — every change is deterministic tool-action code.
- **Structural markdown extraction for `get_content`**: Replaced the flat `page.innerText('body')` call with a purpose-built, dependency-free in-browser walker that preserves headings, list items, links, code spans and paragraph breaks. Single `page.evaluate()` round trip, no new npm dependency. The surrounding truncation / `<content_stats>` / link-stripping pipeline is unchanged.
- **Headless / headed launch hardening**: `resolveLaunchConfig(config, isRoot)` is a pure function so it can be unit-tested without Chromium. `headless: true` now applies a fixed 1280×720 viewport + automation-detection / background-throttle hardening args; `headless: false` uses `viewport: null` so the real OS window drives page size, and the new `isDisplayAvailable()` check throws immediately with an actionable "run under xvfb-run" message instead of an opaque Chromium crash when no display server is present on Linux/macOS/Windows. New optional config: `window_size` / `window_position`. `launchConfig.test.ts` covers both.
- **`wait_for_element` action**: Wires Playwright's `locator.waitFor({ state })` with a `timeout_ms` (100–60000, default 10000) and a state parameter (`visible` | `hidden` | `attached` | `detached`, default `visible`). Marked read-only in the security classifier. Cheaper than the `wait` + `get_state` polling pattern.
- **Ported `secretRedaction.ts` and `totp.ts` helpers from browser-use**: TOTP code generation (HMAC-SHA1, 6 digits, 30s period, strict base32 validation), and `<secret>`-tag secret redaction with `*.`-wildcard domain matching. Used by the browser tool's secret-injection paths.

### Fixed

The `autoSwitchedToNewTab` field required a load-bearing read-modify-write dance at three call sites in `navigate()` / `click()` because `refreshLiveState`'s default clobbered it; now a tri-state (`null` preserves, `true` sets, `false` clears) so the dance collapses to a single read. `getBrowserState()` now runs scroll metadata, tab count and the expensive DOM-tree build in parallel via `Promise.all` instead of sequencing. `emitLiveState()` now try/catches each listener so one bad subscriber cannot break the loop. The redundant ENOENT catch-branch in `uploadFile()` is dropped (the pre-`setInputFiles` `fs.existsSync` already covers it). Magic truncation lookback numbers (500 / 200) and the capture-preview cap (300) are now named constants. `DEFAULT_INCLUDE_ATTRIBUTES` in `domTypes.ts` was missing six upstream entries (`data-mask`, `data-inputmask`, `data-datepicker`, `format`, `expected_format`, `ax_name`); restored. The non-obvious `highlightElements: false` default in `domService.getClickableElements()` (upstream is `true`) is now commented to explain the deliberate local deviation. tsc clean, all WBT tests pass (194/0 in `WebBrowserTool.test.ts`, 7/0 in `domService.test.ts`, 4/0 in `domTreeScript.test.ts`, 14/0 in `launchConfig.test.ts`, 10/0 in `WebBrowserTool.newtab.test.ts`).

- **Built-in code-reviewer agent and agent-run persistence**: `AgentTool/built-in/codeReviewerAgent.ts` ships as a built-in agent type, and `runAgent.ts` persists a run so its transcript survives the spawning turn.
- **Permission prompt result schema and filesystem scoping**: `utils/permissions/PermissionPromptToolResultSchema.ts` validates what a permission-prompt tool returns before it is trusted, and `utils/permissions/filesystem.ts` resolves path rules so a rule cannot grant access outside the directory it names.

- **MCP token refresh locking and paginated listings**: `services/mcp/refreshLock.ts` serializes OAuth token refresh so concurrent tool calls no longer race and invalidate each other's token, and `services/mcp/pagination.ts` follows cursors when a server returns tools or resources in pages instead of stopping at the first page.

- **Background task finalization and routing**: `src/cli/bgFinalizer.ts` settles a background task's final state (with fixture and tests) and `bgRouting.ts` decides where its output goes, both now wired into `bg.ts` and `bgRegistry.ts`. Adds `taskNotificationIdentity.ts` so a completion notification can be matched back to the task that produced it instead of relying on ordering.
- **`--print` flag handling and max-turns reporting**: New `utils/printFlag.ts` centralizes print-mode detection, and `utils/replMaxTurns.ts` backs the REPL's max-turns prop so a run that stops on the turn limit says so in both REPL and print output.
- **Interruption trace infrastructure**: New `src/utils/interruptionTrace.ts` records why and where a run was interrupted, and is now threaded through every surface that can end one — REPL (`replInterruption.ts`), print mode (`cli/printInterruption.ts`), the SDK (`entrypoints/sdk/interruption.ts`), the gRPC server, remote bridges, background-task navigation, teammate views, graceful shutdown, `SendMessageTool` shutdown, in-process swarm spawning, and the Codex/OpenAI provider streams. Previously the trace module existed with 10 importers against the reference's 39, so most interruption paths reported nothing. Adds `backgroundSessionTermination.ts` and companion tests/fixtures for each surface.
- **Unified abort signal plumbing**: `combinedAbortSignal.ts`, `abortController.ts`, `QueryGuard.ts`, and `queryLifecycle.ts` now share one cancellation path, so `useCancelRequest` and shutdown both cancel through the same signal rather than racing separate controllers.
- **Bedrock `anthropic_beta` workaround is now actually wired**: `bedrockClient.ts` held a working fix for an upstream SDK bug but nothing constructed it — `client.ts` instantiated the unpatched `AnthropicBedrock`. It is now a `createBedrockClientClass(Base)` factory over the runtime-loaded SDK export, cached per base class so `instanceof` identity holds across clients. Delivered as a factory rather than a static `extends` because the SDK is loaded on demand; the module's `import type` is erased at compile time, so bundling it does not pull `@anthropic-ai/bedrock-sdk` (or its static `@aws-sdk/client-bedrock-runtime` import) into the CLI bundle — verified at +1,645 bytes with the specifier count unchanged.
- **Production React bundling in the CLI build**: `scripts/build.ts` now remaps `react`, `react/jsx-runtime`, `react/jsx-dev-runtime`, `react-reconciler`, `react-reconciler/constants.js`, and `scheduler` to their production files — 468 KB smaller `dist/cli.mjs` and zero remaining React dev markers. Specifiers resolve via `createRequire().resolve()` instead of hardcoded `node_modules` paths, because Bun's isolated install layout only symlinks direct dependencies into the root; `scheduler` is transitive, so it falls back to resolving from `react-reconciler`. `react/jsx-dev-runtime` maps to a small shim rather than React's real production dev-runtime, which exports `jsxDEV: undefined` by design and would leave every component calling `undefined()`.
- **Build-time packaging hygiene validation**: `validate-externals.ts` now runs `validateInstallHygieneFields` and `validateOptionalPeers` against the repo manifest on every build. Both previously ran only in the opt-in `verify-clean-install.ts`, against the *globally installed* artifact — so a regression surfaced only after a bad manifest had been built and published.
- **`@aws-sdk/client-bedrock` and `@aws-sdk/client-sts` declared in `optionalDependencies`**: both were loaded at runtime but declared in no dependency field, and were the only two provider packages absent from a default install.
- **Node compile-cache launcher and startup benchmark**: `bin/node-compile-cache.mjs`, `scripts/benchmark-gakrcli-startup.mjs`, and `scripts/gakrcli-bin-compile-cache.test.ts` with its instrumentation fixture.
- **`/model` custom model name entry**: The `/model` picker now ends with an `Enter model name…` row. Selecting it swaps the list for a free-text field, so a model can be switched to by typing its name — no `/provider` → edit → navigate-every-field round trip. This is the fix for custom / unlisted OpenAI- and Anthropic-compatible providers, whose routes discovery cannot enumerate and whose picker previously offered only the configured default. Gated behind a new `allowCustomModelInput` prop so the embedded pickers (`PromptInput`, `/config`) keep their fixed choice sets. List navigation wraps, so the row is one `↑` from the top of a 100+ model catalog.
- **Dynamic model discovery for 22 more provider routes**: `openai`, `deepseek`, `moonshot`, `xai`, `venice`, `longcat`, `zai`, `nearai`, `fireworks`, `bankr`, `xiaomi-mimo`, `together`, `mistral`, `dashscope-intl`, `dashscope-cn`, `atlas-cloud`, `gitlawb-opengateway`, `kimi-code`, `clinepass`, `opencode`, `opencode-go`, and `xiaomi-mimo-token` moved from `source: 'static'` to `'hybrid'` with `discovery: { kind: 'openai-compatible' }`. Each route's `GET {baseUrl}/models` endpoint was probed first to confirm it exists. Routes with discovery went from 9 to 31; the 8 that stay static do so because they do not expose an OpenAI-shaped catalog — `azure-openai` (deployments API), `bedrock` (SigV4 `ListFoundationModels`), `cloudflare` (no default base URL, account-scoped), `gemini` (native API shape), `github` / `github-enterprise` (GitHub Models catalog API), `minimax` (anthropic-proxy transport), and `vertex` (Google auth). Static entries still win on `apiName` collision, so hand-authored context windows, capabilities, and reasoning metadata survive the merge, and any discovery failure falls back to the static list.
- **`discoveryModelFilter.ts`**: Shared `mapOpenAIChatCatalogModel` for the routes above. Aggregating providers serve embeddings, rerankers, image/video/speech models, and moderation endpoints from the same `/models` catalog as their chat models; this drops them so they cannot bury usable entries in the picker. Deliberately an exclusion list rather than an allowlist — chat ids vary too much (`glm-5`, `auto`, `inkling`, `mindai/macaron-v1-tall`) for a positive pattern to be safe. Validated against seven live catalogs — 416 ids, 10 removed, all of them genuinely non-chat (`deepseek-ocr`, `gpt-image-2`, three Gemini `-image` variants, `FLUX.2-klein-4B`, `whisper-large-v3`, `Qwen3-Embedding-0.6B`, `Qwen3-Reranker-0.6B`, `openai/privacy-filter`) and no chat model dropped. It also picks up `contextWindow` / `maxOutputTokens` from the common field spellings and honors inline `active: false` / `isAvailable: false`.
- **Discovery status line and manual refresh are now rendered in the picker**: `ModelPicker` already accepted `discoveryState` and `onRefresh`, and `modelPicker:refresh` was already bound to `r` in the keybinding registry, but neither prop was read in the component body — so the "Loaded fresh … models" / "Using cached …" line never appeared and `r` did nothing. The status line now renders under the session-model line, colored by tone, and `r` is wired through `useKeybindings`. The `r to refresh models` hint only appears when the route can actually refresh. Both are suppressed while the custom model-name field is open, otherwise typing `r` would fire a refresh instead of inserting the character.
- **`sdk` as a first-class agent source**: Agents supplied programmatically through the SDK's `agents` option now carry `source: 'sdk'` instead of being forced into the custom-agent shape. `loadAgentsDir.ts` gains an `SdkAgentDefinition` variant (prompt held in a closure, like plugin agents) and `isCustomAgent` stops claiming them, `getActiveAgentsFromList` places them between CLI-arg and managed agents in the override chain, and the source is threaded through every surface that renders one: an `SDK agents` group in `AGENT_SOURCE_GROUPS`, an `SDK` label in `getSourceDisplayName`, a slot in `ContextVisualization`'s display order, and the `Agent` shape in `analyzeContext.ts`. `agentFileUtils.ts` reports `SDK agent` for the relative path and throws for the absolute one, because an SDK agent has no file on disk to open.
- **SDK session agents, heartbeat messages, `ultracode` effort and per-agent `maxSteps`**: `SDKSessionOptions` accepts `agents`, so a v2 session can register agent definitions the same way `query()` already could; definitions are built and merged through `buildSdkUserAgents` / `mergeSdkUserAgents`, and a malformed one is reported as an `agent_load_failure` with `stage: 'injection'` rather than failing the whole session. Per-definition load errors from `failedFiles` are now reported individually instead of being swallowed when the directory scan itself succeeds. Adds `SDKHeartbeatMessage` (`system` / `heartbeat`) to the message union — an opt-in headless liveness signal carrying state, phase, elapsed and idle time, pending permission count and background-task tallies, for `--print` runs that go quiet. `supportedEffortLevels` gains `ultracode`, and `AgentDefinition` gains `maxSteps`. `agents[].description` is now optional, and the `tools` / `disallowedTools` docs state the actual precedence: `['*']` means all subagent tools, and deny entries always override the allowlist.
- **Verified process identity for background sessions**: Each background session now launches with a 32-byte random marker passed as `--gakrcli-bg-session-marker` (`bgRouting.ts`, hidden from help and validated by commander with `InvalidArgumentError`). `bgRegistry.ts` stores it on the session and `bg.ts` checks the live process's command line against it before signalling, so a PID that has been recycled by an unrelated process is no longer a valid target. When identity cannot be established GakrCLI refuses to signal and says so; sessions recorded before this change report that they cannot be verified and suggest a restart, rather than being silently trusted or silently skipped. The marker is stripped from forwarded child argv so it cannot leak into a nested invocation. Sessions also carry an optional `kind` label for the autonomy status view.
- **`--yolo` as an alias for `--dangerously-skip-permissions`**: Registered as a native commander alias on the main command, the internal `open` subcommand and the SSH subcommand, so both spellings resolve to the same parsed option and inherit the flag's arity and `--` handling. `skillsCli.ts` accepts it as a trailing global flag. The root/sudo refusal in `setup.ts` now names the whole family of bypass entry points (`--dangerously-skip-permissions` / `--yolo`, `--allow-dangerously-skip-permissions`, `fullAccess`) instead of just the one flag, which is what it actually rejects.

### Fixed
- **AskUserQuestion result crash took down the whole message list on resume**: `AskUserQuestionTool.renderToolResultMessage` destructured `{ answers }` straight off the tool result, so a `null` result — produced when a resumed session replayed a raw `toolUseResult` from JSONL (which is deserialized without validation) or from a deferred AskUserQuestion — threw `Cannot destructure property 'answers' of 'object null'`. The throw landed inside `MessagesBoundary`, which then rendered the error UI instead of the message list, so the agent kept running but nothing after that message appeared. The renderer now falls back to `{}` for a `null`/missing `answers`, and `AskUserQuestionResultMessage` defaults `answers` to `{}`, so a stripped result can no longer blank the conversation. Regression covered by `AskUserQuestionTool.test.tsx`.
- **AskUserQuestion invoked via ExecuteExtraTool returned empty answers**: the model sometimes called `AskUserQuestion` through `ExecuteExtraTool`. `ExecuteExtraTool.call()` delegates straight to `targetTool.call()`, bypassing the permission pipeline that renders the interactive picker — so the user got a generic "proceed?" prompt instead of the question selector, and the tool returned the model-supplied empty `answers` (a blank "User answered" line). `ExecuteExtraTool` now refuses any `requiresUserInteraction()` tool and tells the model to invoke it directly, where the real picker runs. Regression covered by `ExecuteTool.runner.ts`.
- **WebBrowser schema rejected calls from non-Anthropic providers**: The tool's action union relied on a discriminator that OpenAI-compatible shims serialize differently, so after switching model or provider every call failed with `invalid_union` / "No matching discriminator" before the browser ever launched. The schema now accepts both serializations.
- **Optional AWS SDKs threw a bare `ERR_MODULE_NOT_FOUND`**: `src/utils/model/bedrock.ts` and `src/utils/aws.ts` loaded `@aws-sdk/client-bedrock` and `@aws-sdk/client-sts` with a plain `await import()`, so on an install without them the failure carried no hint about what to install. Both now go through `importOptionalRuntimeModule` with a `typeof import(...)` generic, which reports the missing package and the install command while keeping every call site fully typed. The `@smithy/*` and `credential-providers` sites stay plain imports on purpose — they live in `dependencies`, so they are always installed and cannot fail this way.
- **`client.optionalRuntime.test.ts` passed alone but timed out in a multi-file run**: each test deliberately re-imports `client.js` with a cache-busting query to get a virgin module, which costs the full `client.ts` import graph (~6 s) against bun's 5 s default. The fresh import is the mechanism under test, so the per-test budget is now explicit rather than worked around.
- **The in-REPL model shortcut ignored the configured provider**: `PromptInput` rendered `ModelPicker` bare — no `optionsOverride`, no `discoveryState`, no `onRefresh` — so the hotkey picker offered only the built-in Anthropic models regardless of which provider was active, while `/model` showed the right list. The discovery plumbing is now extracted into `ModelPickerWithDiscovery` (shared by both surfaces) plus `ModelPickerWithLazyDiscovery` for callers that cannot await the context before rendering, which is the hotkey's case: `/model` resolves it in its async `call`, the hotkey toggles synchronously. The lazy variant renders nothing until the context settles rather than mounting the picker first, because mounting first would flash the Anthropic list before the provider's models replaced it — resolving reads the discovery cache, not the network, so the gap is not user-visible. A failed load still opens the picker with the built-in options instead of leaving the hotkey dead. The machinery stays in `model.tsx` rather than moving to a new module: `model.test.tsx` cache-busts via `./model.js?<suffix>` re-imports, and a separate non-cache-busted module would quietly break that isolation.
- **Custom model-name entry bypassed the organization allowlist**: `/model`'s `handleSelect` checks `isModelAllowed`, but `PromptInput`'s `handleModelSelect` does not, and the free-text field is the one path into the picker that skips the vetted option list. `isModelAllowed` is now enforced at submit time in the picker itself, with the error shown inline so the field stays open to retype — the post-selection callers can only close the picker with a message. No change for users without `availableModels` configured.
- **`GET /models` responses with a top-level array were read as empty**: `listOpenAICompatibleModels` and `fetchOpenAICompatibleModelsRaw` only ever read `data.data`. Providers that return the array at the top level instead of inside the OpenAI `{ object: 'list', data: [...] }` envelope therefore looked like "no models", and discovery silently fell back to the static catalog with no error. Both now normalize through a shared `normalizeModelsListPayload` that accepts a bare array, `data`, or `models`, preserving the previous return values for standard payloads.
- **A proto-named permission rule wiped a whole settings file**: `getCustomValidation` looked its tool name up in the plain-object `TOOL_VALIDATION_CONFIG.customValidation` with a bare bracket access, so the prototype chain was live. `validatePermissionRule` gates tool names on an uppercase first character, which rejects the lowercase prototype members, but the double-underscore ones slip through because `'_'.toUpperCase() === '_'`. A rule like `__proto__(x)` therefore resolved an inherited `Object.prototype` value — for `__defineGetter__(x)`, a real inherited function — which the caller treated as a configured validator and invoked, throwing an uncaught `TypeError`. That throw escaped `filterInvalidPermissionRules`, whose entire purpose is to skip one bad rule without rejecting the file: for a project `.gakrcli/settings.json` the caller's `catch` discarded the file's settings and reported no errors, and `parseCommandOutputAsSettings` (MDM) has no `catch` at all, so a single hostile or fat-fingered rule in an untrusted cloned repo silently wiped that file's configuration. The lookup is now guarded with `Object.hasOwn`, so an unrecognized tool name resolves to `undefined` and the rule validates as an ordinary inert rule, mirroring the `normalizeLegacyToolName` hardening already applied to the sibling `LEGACY_TOOL_NAME_ALIASES` lookup.
- **`--bare` was discarded when it preceded the `skills` subcommand**: `cli.tsx`'s skills fast path rewrites `process.argv` to `args.slice(indexOf('skills'))` so commander sees the subcommand at position 0, which silently threw away every global flag typed before it. `--bare skills list` therefore ran full auto-discovery and printed the ~150 seeded bundled skills, while `skills list --bare` correctly printed `Skills: 0 enabled`. The `GAKR_CODE_SIMPLE` hoist now happens above the fast path, so `isBareMode()` is already true by the time the slice runs and both orderings behave identically.
- **The permission-bypass status notice read raw argv**: `statusNoticeDefinitions.tsx` scanned `process.argv` for `--dangerously-skip-permissions`, so the notice missed the new `--yolo` spelling, missed `fullAccess` entirely, and could fire on a literal argument that merely happened to look like the flag (anything after `--`). It now keys off the resolved permission mode via `isDangerousMode` / `isFullAccessMode` — including the kebab-case `full-access` alias — and renders mode-appropriate copy instead of one hardcoded string.
- **An SDK permission allow could outrace a plan-mode switch**: `permissions.ts` revalidated plan mode on only one of the two external-allow paths, so a `canUseTool` / `onPermissionRequest` answer that arrived after the session entered plan mode could still be honored on the other. Both paths now go through a shared `revalidateExternalAllow` helper.
- **`setPermissionMode()` dropped every MCP tool**: `query.ts` refreshed the engine's tool list with a bare `getTools(context)`, which does not include the tools contributed by connected MCP servers, so changing permission mode mid-session silently unregistered them for the rest of the query. Connected MCP tools are now retained on the query and both the initial registration and the refresh go through `assembleToolPool`, which is the same path the REPL uses.
- **`forkSession()` ignored `resumeSessionAt`**: the fork was taken from the full session and the resume point was then applied when loading the forked transcript, so the fork itself contained messages past the requested point. The message id is now passed to `forkSession` as `upToMessageId` and no longer re-applied on load.
- **The SDK env mutex could be released without being held**: the `finally` block released it whenever `envOverrides` were configured, including when `acquireEnvMutex()` itself threw or the run failed before reaching it. Release is now gated on an `envMutexAcquired` flag set immediately after a successful acquire.
- **Agent load failures could be swallowed for an entire query**: failures were queued but only drained around engine yields, so a query whose agents all failed to load and which then produced no engine output reported nothing. The queue is now also drained once before the prompt is submitted. Injection failure additionally clears `agentDefinitions` from app state, which previously kept advertising agents the engine had never received.
- **`bun test` collected the gitignored `package/` tree**: the build's staging directory contains a stale pre-rebranding copy of the built-in agents (`claudeCodeGuideAgent.ts` against a rebranded `builtInAgents.ts` import), so two `resumeAgent.test.ts` cases failed on `Cannot find module './built-in/gakrcliCodeGuideAgent.js'` in a tree with zero tracked files. The `test`, `test:full` and `test:coverage` scripts now exclude `package/**` alongside the existing `dist/**` exclusion, rather than the generated output being edited.
- **The model alias resolver dropped the `[1m]` context-window tag**: `parseUserSpecifiedModel` derived the model string from `has1mContext()` (which also requires the 1M flag to be enabled) instead of the tag's mere *syntax* presence, so aliases like `sonnet`, `opus`, `haiku`, `opusplan`, `best`, `codexplan` and `codexspark` silently lost the `[1m]` suffix whenever 1M context was disabled.
